# Known issues (v1.0.0)

1. **S1 latency target missed.** At 1,000 rps the median of three runs was
   p99 90.08 ms (range 85.22–98.37) against a 50 ms target. Every request
   degraded through `FEATURE_TIMEOUT`. The feature Lua script needs up to three
   Redis round-trips per P2P/bank-transfer event; at this rate they queue.
   Measured ceiling and next steps are in `docs/benchmarks.md`.
2. **Detection targets missed in the measured window.** The partial one-day
   replay gives 88.9% recall at 1.34% FPR and 70.5% recall at ≤1% FPR. Targets
   are ≥85% at ≤1% FPR, ≤1% FPR and ≥+10 points lift; all three miss. The full
   90-day replay was not run because it is CPU-bound at ~15 events/s on this
   host.
3. **C8, C9, C11 not run.** Network partition, disk-full and clock-skew tests
   need host privileges (`CAP_NET_ADMIN`, loopback mount, clock change) that
   this environment does not grant. They are reported as NOT_RUN, not PASS.
4. **Go toolchain vulnerabilities.** `govulncheck` reports 55 reachable stdlib
   advisories on Go 1.23.4; the fix requires Go 1.23.5+ and a toolchain bump
   that was not applied in this window.
5. **Scanner gaps.** `pip-audit`, `bandit`, `npm audit`, `trivy`, `hadolint`,
   `checkov`/`kics`, `gitleaks`, `syft` and `cosign` are not installed in this
   environment. Their absence is recorded in `docs/security.md`; no clean
   result is claimed for them.
6. **Evaluation labels are synthetic.** `data/eval` (seed 2027) is generated by
   the project's own simulator. The numbers measure the engine against that
   generator, not production fraud.
7. **ML scorer is a single process.** Horizontal scorer scaling and model
   hot-reload under load were not exercised.
8. **Duplicate `tune` target warning** in the Makefile is pre-existing and
   does not affect the release targets.
