# FADE v1.0.0 release notes

Release date: 2026-11-19
Branch: `phase/8-release`
Engine version: `1.0.0`

FADE 1.0.0 is the first end-to-end, offline-runnable release: ingestion through
Redpanda, Go feature and decision pipeline, Python ML scorer, PostgreSQL audit
trail, case management, analyst dashboard and operations tooling.

## What is in the release

- `cmd/decision-api`: synchronous decision endpoint, idempotency, circuit
  breaker, degraded modes, `/metrics`, OpenAPI.
- `cmd/feature-worker`, `cmd/case-worker`, `cmd/replay-worker`: stream workers.
- `cmd/replay`: deterministic replay with baseline/candidate comparison,
  per-scenario metrics, confidence intervals and McNemar tests.
- `ml/serve`: FastAPI scorer with single-flight model loading, SHAP
  explanations and vectorised batch scoring.
- `dashboard`: Next.js case queue, decision detail, replay and rule views.
- `deploy/`: Compose profiles, Dockerfiles, Prometheus rules, Grafana board.

## Upgrade

From 0.9.x:

1. Back up PostgreSQL and Redis (`make backup`).
2. Pull the new images and run `make migrate`; migrations are additive and
   idempotent.
3. Roll the decision API, then the workers. The decision API tolerates the
   previous worker version during the overlap.
4. Run `fade features backfill` only if Redis state was lost; it is idempotent.

## Known issues

- S1 target missed; feature-stage timeouts at 1,000 rps.
- Detection targets missed in the available one-day window; full 90-day replay
  is too slow on the reference host (see `docs/known-issues.md`).
- C8, C9, C11 cannot run without host privileges.
- Container images are pinned by tag in the repository; digest pinning must be
  completed with registry access before a public image release.
